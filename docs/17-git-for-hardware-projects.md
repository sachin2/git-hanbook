# 17 · Git for Hardware / EDA Projects

FPGA and ASIC tools were not designed with version control in mind: they generate thousands of files, store absolute paths, write binary databases, and regenerate project files on every open. The key principle:

> **Version the *sources* and the *scripts that rebuild the project*, never the tool's generated project state.**

## What to commit vs. ignore

| Commit ✅ | Ignore ❌ |
|---|---|
| HDL: `*.v`, `*.sv`, `*.vhd`, packages, includes | Tool run directories (`*.runs/`, `*.cache/`, `*.sim/`, `work/`, `xsim.dir/`) |
| Testbenches, cocotb/UVM sources, test vectors | Waveforms (`*.vcd`, `*.fst`, `*.wdb`, `*.shm/`) — unless a small golden reference |
| Constraints: `*.xdc`, `*.sdc`, `*.pcf`, `*.lpf`, `*.qsf` (Quartus settings) | Logs and journals (`*.log`, `*.jou`, `*.str`, `vivado_pid*`) |
| Tcl/Makefile/FuseSoC/Edalize/OpenLane config that recreates the project | Generated netlists, `*.dcp` checkpoints, bitstreams (→ release artefacts/LFS) |
| IP configuration: `*.xci` (Vivado), `*.ip` / `*.qsys` (Quartus) | Generated IP output products (`ip/*/sim/`, `synth/`, `*.dcp` inside IP dirs) |
| Block design exported as Tcl (`write_bd_tcl`) | `*.bd` internals regenerated by the tool, `.Xil/`, `.hbs/` |
| Software/firmware sources, linker scripts, Vitis/SDK *source* | Vitis/SDK workspace metadata, `.metadata/`, `Debug/`, `Release/` |
| Documentation, block diagrams (source form, e.g. drawio/svg) | Editor & OS junk |
| Analog: schematic/layout sources if text-based or required; SPICE netlists; testbench decks | Simulator scratch (`*.raw`, `psf/`, `simulation/`), Virtuoso lock files (`*.cdslck`) |

Ready-made templates: [`examples/gitignore/vivado.gitignore`](../examples/gitignore/vivado.gitignore), [`quartus.gitignore`](../examples/gitignore/quartus.gitignore), [`eda-asic.gitignore`](../examples/gitignore/eda-asic.gitignore).

## Vivado: script the project

Instead of committing `project.xpr` + runs:

```tcl
# In the Vivado Tcl console, once:
write_project_tcl -force -no_copy_sources -use_bd_files ./scripts/recreate_project.tcl
# For block designs:
write_bd_tcl -force ./bd/system_bd.tcl
```

Rebuild anywhere:

```bash
vivado -mode batch -source scripts/recreate_project.tcl
```

Better still, keep a hand-maintained, readable `build.tcl` (create_project, add_files, read_xdc, set_property, create_ip …) — the generated `write_project_tcl` output contains absolute paths and tool-version cruft that changes every regeneration.

### Vivado gotchas

- **Version lock-in:** IP (`*.xci`) and block designs are tied to the Vivado version. Record the version in the README (and in the Tcl: `if {[version -short] ne "2023.2"} {…}`). Upgrading = a dedicated commit with `upgrade_ip`.
- **Absolute paths** leak into generated Tcl and `.xpr`. Review diffs; use `[file normalize [file dirname [info script]]]` for script-relative paths.
- `*.xci` changes on every open (timestamps). Commit only meaningful changes; `git add -p` helps.
- Line endings: force `*.tcl text eol=lf`, `*.xdc text eol=lf` in `.gitattributes`.
- Keep the project directory **outside** the source tree (e.g. `build/`), so `git status` stays clean.

## Quartus

Commit `*.qpf`, `*.qsf`, `*.sdc`, `*.qsys`/`*.ip`, HDL. Ignore `db/`, `incremental_db/`, `output_files/`, `*.qws`, `greybox_tmp/`, `simulation/`. `quartus_sh -t` scripts recreate projects.

## ASIC flows (open-source and commercial)

- Commit: RTL, constraints (SDC), flow configuration (OpenLane/OpenROAD `config.json`/`config.tcl`, Makefiles), custom scripts, LEF/LIB **only if** you are licensed to and they're your own cells.
- Ignore: `runs/`, `results/`, `reports/` (keep a summary CSV/Markdown of key metrics instead), `objects/`, `logs/`, `tmp/`.
- **PDK files: usually never commit.** Commercial PDKs are under NDA; open PDKs (sky130, gf180mcu, IHP SG13G2) are better installed via `volare`/package manager and referenced by version in config.
- Final GDS/OAS for tapeout: tag the commit (`git tag -a tapeout-2026-11 -m "…"`) and store the GDS in LFS or an artefact store with the tag name — *not* as plain blobs.
- Cadence Virtuoso libraries are directories of binary `*.oa` files — Git can store them but cannot merge them. Use **one owner per cell view**, LFS for large data, or a dedicated DM tool (Cliosoft SOS, DesignSync) where the team mandates it. Ignore `*.cdslck`, `.cadence/`, `CDS.log*`, `panic.log`.

## Binaries and bitstreams

- Bitstreams, `.xsa`/`.hdf`, `.elf`, GDS are **build outputs**. Prefer CI artefacts / GitHub Releases attached to a tag.
- If they must be in the repo: Git LFS.
  ```bash
  git lfs install
  git lfs track "*.bit" "*.bin" "*.xsa" "*.gds" "*.oas" "*.dcp"
  git add .gitattributes
  ```
- Mark them binary in `.gitattributes` even without LFS so Git never tries to merge or diff them:
  ```gitattributes
  *.bit binary
  *.gds binary
  *.dcp binary
  ```

## Traceability: put the Git hash in the hardware

Embed the commit ID into a version/ID register so any board or chip can tell you exactly which source built it.

```tcl
# Vivado: pass as a generic / define at synthesis
set git_hash [exec git rev-parse --short=8 HEAD]
set_property generic "G_GIT_HASH=32'h$git_hash" [current_fileset]
# also mark dirty builds:
if {[catch {exec git diff --quiet}]} { puts "WARNING: building from a dirty tree" }
```

```systemverilog
module version_reg #(parameter logic [31:0] G_GIT_HASH = '0) (...);
```

Use `git describe --always --dirty --tags` for a human-readable version string in firmware.

## Simulation & regression in CI

- Run open-source simulators (Verilator, Icarus, GHDL, cocotb) on every push; commercial ones on a self-hosted runner.
- Lint (`verilator --lint-only`, `verible-verilog-lint`) in a pre-commit hook.
- `git bisect run ./run_regression.sh` finds the commit that broke a test automatically — only works if each commit builds.

## Collaboration tips for hardware teams

- Split big designs into IP blocks with clear owners (CODEOWNERS per directory).
- Submodules for shared IP libraries pinned to a version; tag IP releases.
- Avoid simultaneous edits of non-mergeable files (block designs, schematics) — communicate, or use `git lfs lock` for exclusive locking:
  ```bash
  git lfs track "*.bd" --lockable
  git lfs lock bd/system.bd
  git lfs unlock bd/system.bd
  ```
- Review constraint changes as carefully as RTL — a one-line XDC/SDC change can break timing on the whole design.
